# SQL 읽기 · 판정 규칙

`refac-sql` 리뷰어가 대조하는 **유일한 기준**입니다.
여기 없는 것을 규칙이라고 제안하면 검증에서 `V-3` 으로 반려됩니다.

## 0. 화면이 밖으로 나가는 길은 셋입니다 — 셋을 섞지 마세요

**이 절을 안 읽으면 나머지가 전부 오탐이 됩니다.** 호출 방식마다 본문이 있는
곳이 다르고, **하나는 아예 저장소에 없습니다.**

전부 TibRV 로 나가고, **첫 번째 인자가 무엇을 하는 호출인지 말해 줍니다.**

```csharp
SendMessageWithJSON(SQLEXEC, …, _sql.GetSql(), 60)
SendMessageWithJSON(DPICALL, …, "mat.selectTrimMatId", _appName, _param)
SendMessage("LOTCOMMENT", …, m_StrAppname, Params, 30)
SendMessageWithJSONToTextResult(SET_SIMAXDATA, …, "legacy_semis.updateSemisDelivery", …)
```

| 첫 인자 | 무엇인가 | 본문은 어디에 | 당신이 할 일 |
|---|---|---|---|
| `DPICALL` · `DPIEXEC` | iBATIS mapper 의 SQL ID | `<작업폴더>/src-sql/` | **읽고 판정합니다** (`Q-1`~`Q-9`) |
| `SQLEXEC` | 화면이 `_sql` 에 조립해 둔 SQL. **ID 가 없습니다** | `<작업폴더>/src/` — 화면 안 | **읽고 판정합니다.** XML 이 없는 것이 정상입니다 |
| **그 밖의 전부** | **Rule 시스템 메시지** — `SET_SIMAXDATA` · `LOTCOMMENT` · `TKIN` · `TKOUT` · `ISSUE` … | **어디에도 없습니다** | **그냥 지나갑니다** |

### Rule 메시지는 찾지 마세요

백엔드 API 호출입니다. 로직은 **Rule 시스템 쪽에 있고 이 저장소에
들어오지 않습니다.**

**`SET_SIMAXDATA` 가 특히 헷갈립니다.** 뒤에 붙는
`"legacy_semis.updateSemisDelivery"` 가 SQL ID 와 똑같이 생겼거든요.
**mapper 에 없습니다.** 쫓아가면 영원히 못 찾습니다.

그래서:

- mapper 에서 **찾지 마세요.** 없는 것이 정상입니다
- 검색기로 저장소 밖을 **뒤지지 마세요.** 거기에도 없습니다
- **「정의 없음」으로 올리지 마세요.** 멀쩡히 도는 호출을
  "실행하면 터진다"로 회의 자료에 싣는 것입니다
- `확인 못 한 것` 에 적을 필요도 **없습니다.** 확인 대상이 아닙니다

인덱서가 이미 갈라 두었습니다 — `1-index.json` 의 `sql.ruleMessages` 가
그것이고, `sql.called` 에는 애초에 들어가지 않습니다.

> 이 메시지들에 대해 할 말이 있다면 하나뿐입니다:
> **"이 화면은 Rule 시스템 메시지 N개를 부릅니다"** — 그 이상은 이 리포트의 범위 밖입니다.

판정 규칙은 **화이트리스트**입니다. `DPICALL`·`DPIEXEC`·`SQLEXEC` 만 SQL 을 가진
종류로 알고, **RV 로 나가는 나머지는 전부 Rule 로 봅니다.** Rule 메시지 이름은
계속 늘기 때문에 열거할 수 없습니다 — 새 메시지가 생겨도 저절로 맞습니다.

## 1. 필요한 mapper 만 이미 수집돼 있습니다

`collect.py` 는 mapper 트리를 **통째로 가져오지 않습니다.**
DPI mapper 저장소는 전사 공용이라 dao 폴더 하나에 XML 이 수백 개 있고,
그중 이 화면이 부르는 것은 보통 서너 개입니다.

그래서 **코드를 먼저 읽고, 거기 나온 SQL ID 의 네임스페이스에 해당하는 파일만**
골라 `<작업폴더>/src-sql/` 로 가져옵니다.

```
<작업폴더>/
├── src/          대상 소스 (C# · XAML)
└── src-sql/      이 코드가 부르는 mapper 만   ← 여기
```

**`read`·`grep` 도구로 그냥 읽으세요.** 저장소 밖을 뒤질 필요가 없습니다.

선별 근거는 `1-meta.json` 의 `sources` 에 남습니다.

| 항목 | 뜻 |
|---|---|
| `sqlIdsCalled` | 코드에서 찾은 SQL ID 전부 |
| `namespacesNeeded` | 그 ID 들의 네임스페이스 |
| `namespacesNotFound` | **mapper 파일을 못 찾은 네임스페이스** — 본문을 못 읽었다는 뜻 |
| `mapperFilesTrimmed` | 1MB 를 넘어 **부르는 문장만 잘라 온** 파일. 본문은 읽을 수 있습니다 |
| `mapperFilesUnread` | 자르는 것조차 실패한 파일. 본문을 못 읽었습니다 |
| `ruleMessages` | `SET_SIMAXDATA` 로 나가는 Rule 메시지. **찾지 않습니다** (0절) |
| `mapperFiles` | 실제로 가져온 파일 수 |
| `mapperMode` | `선별` (기본) 또는 `all` (`--all-mappers` 를 준 경우) |

### 잘라 온 파일에서는 「안 쓰는 SQL」을 말할 수 없습니다

`lotMapper.xml` 처럼 한 파일에 SQL 이 수천 개인 것은 1MB 를 넘습니다.
통째로 옮기면 작업 폴더가 부풀어 읽을 것을 못 찾고, 건너뛰면 본문을 아무도
못 읽습니다. 그래서 **이 화면이 부르는 문장만 잘라서** 가져옵니다
(`<include refid>` 로 끌어 쓰는 `<sql>` 조각도 따라옵니다).

파일 맨 위에 잘라 왔다는 머리말이 붙어 있습니다. 그 파일에 대해서는:

- **본문 판정은 그대로 합니다.** `Q-1`~`Q-9` 를 정상적으로 적용하세요
- **「정의됐지만 호출 없음」은 말할 수 없습니다.** 안 쓰는 문장은 애초에
  안 가져왔으니까요. 비어 있는 것이 당연하고, 그것을 근거로
  "안 쓰는 SQL 이 없습니다" 라고 쓰면 거짓이 됩니다

**한 네임스페이스가 파일 하나라고 가정하지 마세요.**
`dao/lot/` 아래에 `lot.xml` 과 `lotMapper.xml` 이 둘 다 `namespace="lot"` 인 것이
DPI 의 기본형입니다. 수집기는 선언된 `namespace` 를 전수로 보고 **그 네임스페이스의
파일을 전부** 가져옵니다. 그래서 `src-sql/` 안에 같은 네임스페이스 파일이
여러 개 있는 것이 정상입니다 — 하나만 읽고 "나머지는 없다"고 보지 마세요.

> `namespacesNotFound` 가 비어 있지 않으면 **그 SQL 의 본문은 읽을 수 없습니다.**
> 추측하지 말고 `확인 못 한 것` 에 적으세요.

### 수집이 안 됐다면

`1-meta.json` 의 `sources.mapper` 가 `null` 이고 `mapperNote` 에 이유가 적혀 있습니다.
대개 `mapper-dir.txt` 에 이 저장소 매핑이 없는 경우입니다.

그때는 **지어내지 말고** `확인 못 한 것` 에 적으세요.

> `lot.selectMcLot` 본문 — `mapper-dir.txt` 에 `ZZ_SWP` 매핑이 없어 읽지 못했습니다.

정말 필요하면 검색기(`rg` · `findstr` · `Select-String`)로 저장소 밖을 볼 수 있습니다.
이 하네스에서 **저장소 밖 검색이 열린 에이전트는 당신뿐**입니다.

```powershell
# PowerShell (팀 기본 환경)
Select-String -Path "D:\Git\DPImgr\...\dao\lot\*.xml" -Pattern 'id="selectMcLot"'
```

```bash
# ripgrep — 있으면 어느 셸에서든 가장 빠릅니다
rg -n 'id="selectMcLot"' "D:/Git/DPImgr/.../dao/lot/"
```

# Q — 판정 규칙

## Q-1 · 값을 문자열로 이어 붙인다

```csharp
AddSql("   AND TRIM(l.line_id) = '" + lineId + "' ");
```

값에 따옴표가 들어오면 쿼리가 깨지고, **의도적으로 넣으면 조건을 바꿔 넣을 수 있습니다.**
바인딩 변수(`#{lineId}` 또는 `_sql.Bind("lineId")`)로 바꾸자고 하세요.

이건 거의 항상 `먼저` 입니다.

## Q-2 · 바인딩 변수와 파라미터가 맞지 않는다

mapper 본문의 `#{...}` 와 화면의 `AddParam(...)` 키를 하나씩 대조하세요.
빠지거나 남는 것이 있으면 **실행 시점에** 터집니다.

## Q-3 · 컬럼을 함수로 감싸 인덱스를 못 탄다

```sql
WHERE TRIM(l.lot_id) = #{lotId}      -- lot_id 인덱스를 못 씁니다
```

`TRIM` · `UPPER` · `SUBSTR` · `TO_CHAR` 가 **컬럼 쪽에** 붙으면 인덱스가 죽습니다.
값 쪽에서 다듬어 넘기자고 하세요.

## Q-4 · 조인 조건이 없거나 콤마 조인이다

```sql
FROM mc_lot l, mc_mat m
WHERE l.mat_key = m.mat_key
```

동작은 하지만 조건을 빠뜨리면 곱집합이 됩니다.
명시적 `JOIN ... ON` 으로 바꾸면 조건이 빠진 것이 눈에 보입니다.

## Q-5 · 정의됐지만 부르는 곳이 없다

`1-index.json` 의 `sql.unusedIds` 입니다.

> **`sql.trimmedMapperFiles` 에 있는 파일은 여기서 빠집니다.**
> 잘라 온 파일이라 안 쓰는 문장이 애초에 없습니다. 그 파일에 대해
> `Q-5` 를 올리지 마세요.

> **`<sql id="…">` 조각은 `unusedIds` 에 들어가지 않습니다.**
> C# 이 부르는 것이 아니라 다른 문장이 `<include refid>` 로 끌어 쓰는 것이라,
> 호출부가 없는 것이 정상입니다. 아무도 `include` 하지 않는 조각만
> `sql.unusedFragments` 에 따로 있습니다.

**이 값의 뜻을 정확히 아세요.** mapper 를 선별해 가져오므로 이렇습니다.

> **이 코드가 부르는 SQL 과 같은 파일에 들어 있으면서, 이 코드는 부르지 않는 SQL**

수집하지 않은 mapper 파일의 SQL 은 애초에 세지 않았습니다. 그러니
"저장소 전체에서 아무도 안 쓴다"는 말이 **아닙니다.**

> **mapper 는 여러 화면이 공유합니다.**
> 이 분석은 **대상 경로 안의 호출만**, 그것도 **가져온 mapper 파일 안에서만** 봤습니다.
> 지우자고 할 때 반드시 이 한계를 함께 적고, `확인 못 한 것` 에도 남기세요.
> 그러지 않으면 다른 화면이 멈춥니다.

## Q-6 · 부르는데 정의가 없다

「부르는데 정의가 안 보인다」에는 **성격이 다른 두 가지**가 섞입니다.
인덱서가 이미 나눠 두었으니 **칸을 보고 가르세요.**

| 인덱스의 칸 | 뜻 | 어떻게 씁니다 |
|---|---|---|
| `sql.missingIds` | 그 네임스페이스의 mapper 를 **읽었는데도** 없습니다 | **진짜 문제.** 실행하면 터집니다 |
| `sql.unverifiedIds` | 그 네임스페이스의 mapper 를 **못 읽었습니다** | 확인 불가. `확인 못 한 것` 에 적습니다 |

`unverifiedIds` 를 "정의가 없습니다" 라고 단정하면 오탐입니다.
**멀쩡히 돌고 있는 SQL 을 "실행하면 터진다"고 회의 자료에 싣는 것**이라 값이 비쌉니다.
`1-index.json` 의 `sql.collectedNamespaces` 가 실제로 본문을 읽은 네임스페이스이고,
`1-meta.json` 의 `namespacesNotFound` · `mapperFilesTooLarge` 에 못 읽은 이유가 남습니다.

`missingIds` 를 올릴 때는, 지금 호출부가 죽은 코드 안에 있어
드러나지 않을 수 있다는 점도 **함께** 적으세요.

## Q-7 · 본문이 사실상 같은 SQL 이 두 ID 로 있다

`1-index.json` 의 `sql.duplicateBodies` 입니다.
어느 쪽을 남길지는 **호출부 수**로 정하세요. 호출이 0인 쪽이 지울 후보입니다.

이름이 내용과 어긋난 경우도 여기서 잡힙니다 —
`selectMcLotList` 인데 단건 조건(`= #{lotId}`)이면 이름이 거짓말을 하고 있습니다.

## Q-8 · `SELECT *` · 필요 없는 컬럼

화면이 쓰지 않는 컬럼까지 실어 오는지 보세요. 행이 많을수록 차이가 납니다.

## Q-9 · 갱신에 조건이 없거나 넓다

`UPDATE` · `DELETE` 에 `WHERE` 가 없거나 키가 아닌 컬럼만 걸린 경우.
**운영 DB 라 되돌릴 수 없습니다.** 발견하면 `먼저` 입니다.

## 우선순위를 붙이는 기준

| 우선순위 | 언제 |
|---|---|
| **먼저** | 값이 그대로 쿼리에 들어가거나(Q-1), 갱신 범위가 위험하거나(Q-9), 실행하면 터지는 것(Q-2·Q-6) |
| **다음** | 지금은 도는데 데이터가 늘면 느려지는 것(Q-3·Q-4·Q-8), 정리하면 좋은 것(Q-5·Q-7) |
| **참고** | 취향·표기 통일 |

## 비용을 붙이는 기준

| 비용 | 언제 |
|---|---|
| **작음** | mapper 파일 한 곳만 고치면 끝 |
| **보통** | mapper 와 화면 코드를 같이 고쳐야 함 (파라미터가 바뀜) |
| **큼** | **다른 화면과 공유하는 SQL** 이라 영향 범위를 먼저 조사해야 함 |

> 공유 mapper 를 고치는 것은 언제나 `큼` 입니다. 이 하네스는 대상 경로만 봤습니다.

## SQL 본문을 리포트에 싣는 법

`findings.json` 의 `sql[]` 에 `Q###` 로 넣습니다. 제안 자체는 `S###` 입니다.

```
S001  제안  — "인라인 SQL 을 문자열 연결로 조립한다"
Q003  본문  — 그 SQL 의 실제 텍스트와 개선점
```

인라인 SQL 의 본문을 옮길 때 **연결되는 값 자리는 그대로 적지 말고**
`'<lineId 문자열 연결>'` 처럼 무엇이 들어오는지 보이게 쓰세요.

## 하지 않는 일

- **이름 규칙은 보지 않습니다.** → `refac-convention`
- **C# 쪽 중복·미참조는 보지 않습니다.** → `refac-hygiene`
  (미사용 **SQL ID** 는 여기, 미사용 **C# 멤버** 는 저기입니다)
- **반복문 구조는 보지 않습니다.** → `refac-design` 의 `A-3`
  (쿼리가 **무엇을 하는지**는 여기, **어떻게 불리는지**는 저기입니다)
- **읽지 못한 SQL 을 추측으로 적지 않습니다.** `확인 못 한 것` 에 남깁니다
